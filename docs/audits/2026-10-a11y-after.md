# Accessibility and mobile re-audit, October 2026

The second pass over the public Rosary site. The first pass
([2026-10-a11y-baseline.md](2026-10-a11y-baseline.md)) ran on 72bda90, before
the rebuilt home, category and prayer pages and the new site shell landed. This
pass ran on `website/rosary-focus` at 7b7023a, fixed what it found, and
re-ran the same checks on the result.

A redesign (a new palette, fonts and logo) follows. This pass therefore fixed
structure, semantics, targets, text size and reflow, and left colour contrast
to the redesign: one contrast fix below is a single class and will be
overwritten by the new palette. Re-run axe on the new colours.

## Scope and method

- Pages: `/`, `/mysteries`, `/mysteries/joyful`, `/mysteries/seven_sorrows`,
  `/meditation-sets/26/pray` in both counting modes (`count=beads`, the
  default, and `count=screen`) and with `form=scriptural`,
  `/mysteries/sorrowful/pray?form=holy&count=screen`, and `/privacy-policy`.
- Widths: 320, 360, 390 and 1280 CSS px. Phone widths with touch enabled.
- axe-core 4.10.0 (WCAG 2.x A and AA, 2.2 AA, best-practice) on every page at
  every width and, on the prayer page, in every state below.
- Keyboard-only walk (order, focus indicator, focus hidden behind another
  element), skip link behaviour, `prefers-reduced-motion: reduce`, and text at
  200% (root font size doubled) as a reflow check.
- Prayer page controls exercised at 320, 390 and 1280: the settings pane
  (open, text size up and down, close), Next, the strand buttons, Complete and
  the completion screen in page mode; Next bead, Space, tapping the words,
  swipe left and right (touch events at 320 and 390), all 82 beads to the last
  one, Complete and the completion screen in screen mode; Pray aloud with the
  spoken player showing.
- Dev-only tool UI (the Tidewave toolbar and a `canvas` from a dev overlay) is
  excluded; neither exists in production.

The baseline had 30 rows; one ("mystery names are not headings") did not
reproduce and is withdrawn (see below), so the baseline column is 29.

Between the baseline and the start of this pass the rebuilt pages and shell
closed every Critical and most Serious items: the tap zones are gone, there is
a skip link and a single `<main>`, Escape closes both menus (re-verified: the
Mysteries menu and the phone menu both set `aria-expanded` to false and return
focus to their button), motion is switched off under reduced motion (no
element animates with `reduce` on), the prayer page announces each bead in an
`aria-live` region, and no page needs sideways scrolling at 320, 360, 390 or
1280.

## Verified clean

- axe: no violations on any page at any width, apart from the dev-only
  overlay noted above, in every prayer state listed (settings open, text at
  maximum and minimum, page 2, closing page, completion in both modes, last
  bead, spoken player on).
- No target under 44 px on any page, except the visually hidden radio inputs
  behind the category pills (their 44 px labels are the target).
- No text under 12 px on any page.
- First Tab stop is "Skip to content" on every page that has the header; it
  moves focus to `<main id="main-content">`. The prayer page hides the header
  and skip link on purpose (two stops before the content); its first stop is
  the exit link.
- Focus indicators: every stop has an outline or box-shadow of its own, or an
  ancestor's (`.category-card:has(.category-stretched-link:focus-visible)`,
  `.category-pill-option:has(:focus-visible)`).
- Swipe: left moves one bead on and right one back, at 320 and 390 px. The
  region has non-gesture equivalents: the Next bead and Previous buttons, and
  Space, Enter and the arrow keys.
- Prayer page status line (`aria-live="polite"`) changes with every bead.

## Correction to the baseline

The baseline listed "the mysteries in the `/mysteries` panel are not headings"
as Moderate. That was wrong. The mystery names were `<h3>` then and are now;
the baseline's heading listing came from a filter that skipped them. The
baseline file keeps the row; this one withdraws it.
